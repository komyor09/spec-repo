# «ВетМед» — Информационная система ветеринарной клиники

Веб-приложение для автоматизации работы ветеринарной клиники с разделением ролей (**Рабочее место врача** и **Личный кабинет владельца питомца**).

Проект реализован с **объектно-ориентированным бэкендом на C# (.NET 8 / ASP.NET Core Web API)** и веб-интерфейсом на React + TypeScript. Поддерживаются два способа запуска: через **`dotnet run`** (основной режим для проверки C# ООП-части) и через **`npm run dev`**.

---

## Стек технологий и архитектура ООП

- **Backend (C# / .NET 8):** ASP.NET Core Web API (`VetMed.sln`, `VetMed.Api/`)
  - **Абстракция и наследование:** базовые абстрактные классы `ClinicEntity`, `PersonBase` (`Owner`, `Veterinarian`), `ClinicalEvent` (`Appointment`, `MedicalRecord`, `Vaccination`, `LabTest`), иерархия исключений `ClinicDomainException` (`DomainValidationException`, `EntityNotFoundException`, `ScheduleConflictException`).
  - **Инкапсуляция:** защита инвариантов в конструкторах и доменных методах (`AnimalPatient.UpdateCareProfile`, `Medication.Dispense`, `Medication.AdjustStock`, `Appointment.ChangeStatus`, `InpatientTask.ToggleCompletion`).
  - **Интерфейсы и DI:** `IClinicRepository`, `IClinicSeedProvider`, `IScheduleValidator`, `IPharmacyService`, `IBillingService`, `IClinicService`.
  - **Полиморфизм:** переопределение `GetDisplaySummary()`, `GetRoleDescription()`, `GetEventTitle()` (сводный вывод доступен по маршруту `/api/clinic/oop-summary`).
- **Frontend:** React 19, TypeScript, Tailwind CSS, Vite
- **Хранение данных:** общий локальный файл `data/clinic-db.json` (создаётся автоматически при первом запуске — установка СУБД не требуется)

## Требования для запуска

1. **.NET 8 SDK** (для запуска C#-сервера через `dotnet run` или Visual Studio 2022 / Rider) — [dotnet.microsoft.com](https://dotnet.microsoft.com/download/dotnet/8.0)
2. **Node.js 20.0+** (включает `npm`, нужен для сборки фронтенда в `dist/` или запуска в dev-режиме через `npm run dev`) — [nodejs.org](https://nodejs.org)

## Способ 1: Запуск на C# через `dotnet run` (основной для проверки предмета)

1. **Откройте терминал в корневой папке проекта** (где лежат `VetMed.sln` и `package.json`).

2. **Установите зависимости фронтенда и соберите статику в `dist/`** (выполняется один раз):
   ```bash
   npm install
   npm run build
   ```
   *(Если при `npm install` возникает ошибка `ERESOLVE`, выполните `npm install --legacy-peer-deps`.)*

3. **Запустите C#-бэкенд (он же раздаст собранный веб-интерфейс):**
   ```bash
   dotnet run --project VetMed.Api
   ```
   *(Либо откройте `VetMed.sln` в Visual Studio 2022 и нажмите **F5** / **Run**.)*

4. **Откройте приложение в браузере:**
   ```text
   http://localhost:3000
   ```

> Если запустить `dotnet run --project VetMed.Api` до выполнения `npm run build`, все API-маршруты (`/api/clinic/state`, `/api/clinic/oop-summary` и др.) всё равно будут работать, а на главной странице появится подсказка о сборке интерфейса.

---

## Способ 2: Быстрый запуск в режиме разработки (`npm run dev`)

Если нужно быстро запустить интерфейс и Node.js-сервер без сборки `dist/`:

1. Установите зависимости:
   ```bash
   npm install
   ```
2. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
3. Откройте в браузере `http://localhost:3000`.

> **Примечание:** Оба сервера (C# `VetMed.Api` и Node `server.ts`) используют один и тот же порт `3000` и общий файл `data/clinic-db.json`, поэтому запускайте их по очереди. При желании запустить C#-сервер на другом порту используйте `dotnet run --project VetMed.Api --urls http://localhost:5080`.

## Проверка кода и демо-данные

- Проверка сборки C#-проекта:
  ```bash
  dotnet build VetMed.sln
  ```
- Проверка типов TypeScript:
  ```bash
  npm run lint
  ```
- При первом запуске автоматически создаётся база `data/clinic-db.json` (8 пациентов, 4 врача, 12 препаратов, записи на приём, анализы, стационар и счета). В интерфейсе есть кнопка **«Сбросить базу данных»**.

## Основные возможности для проверки

В левой боковой панели можно переключаться между двумя ролями:

1. **Рабочее место врача:**
   - **Обзор смены** — ключевые показатели, очередь приёмов, лист стационара и контроль остатков аптеки.
   - **Быстрый поиск в шапке** — мгновенный переход к питомцу (по кличке, породе или микрочипу), владельцу или препарату.
   - **Пациенты и карты** — учёт животных (собаки, кошки, грызуны, птицы, рептилии), электронная история болезни, фиксация осмотров с **автоматическим выставлением счёта владельцу** (с учётом скидки лояльности), прививок, выгрузка `.txt` и **печать / сохранение в PDF**.
   - **Запись и расписание** — планирование визитов с защитой от наложения слотов у одного врача (`409 Conflict`) и сменой статусов приёма.
   - **Стационар и процедуры** — контроль пациентов в боксах и отметка выполнения процедур.
   - **Лаборатория и анализы** — назначение исследований и ввод результатов.
   - **Аптека и склад** — база препаратов с автосписанием при назначении врачом и калькулятором дозировок по весу.
   - **Владельцы и счета** — база клиентов, финансовая сводка, фильтр статусов и **печать квитанций**.

2. **Кабинет владельца:**
   - **Мои питомцы** — паспорта питомцев (микрочип, группа крови, аллергии, диета).
   - **История болезни** — просмотр протоколов осмотров и результатов анализов.
   - **Прививки и обработки** — календарь вакцинаций и обработок со статусами сроков.
   - **Мои записи** — онлайн-запись на приём и отмена визитов.
   - **Назначения и чеки** — домашний план приёма лекарств и оплата счетов.
