# ВетМед — добавление объектно-ориентированного C# (.NET 8) бэкенда

Добавление полноценного серверного решения на **C# (.NET 8 / ASP.NET Core Web API)** с явной реализацией принципов ООП (абстракция, инкапсуляция, наследование, полиморфизм и интерфейсы) при полном сохранении существующего веб-интерфейса и прежнего способа запуска через `npm run dev`.

---

## Подтверждённые решения и важные особенности

> [!IMPORTANT]
> В среде онлайн-предпросмотра сейчас не установлен .NET SDK, поэтому интерактивный предпросмотр и запуск через `npm run dev` продолжат работать на Node.js/Express без каких-либо сбоев, а C#-проект будет построен на чистом стандартном стеке **.NET 8** (без сторонних NuGet-зависимостей), чтобы гарантированно собираться и запускаться командой `dotnet run` у вас на Windows и у преподавателя.

- **Подтверждённый объём:** добавляется только C# (.NET 8) код в проект «ВетМед» (без изменения промта для друга и без переделки интерфейса).
- **Подтверждённая архитектура:** ASP.NET Core Web API полностью повторяет существующие `/api/*` маршруты и работает с тем же файлом `clinic-db.json`, обслуживая текущий веб-интерфейс.
- **Подтверждённая документация:** `README.md` дополняется понятной пошаговой инструкцией запуска через `dotnet run` (и открытия решения в Visual Studio) для преподавателя, с сохранением раздела о `npm run dev`.

## 1. Обзор и цель доработки

- **Что решает доработка:** переводит учебный проект в формат, полностью соответствующий требованиям предмета **«ООП на C#»**, сохраняя уже готовый и согласованный интерфейс клиники.
- **Целевая аудитория:** студент (быстрый запуск через `cmd` и `npm run dev` или `dotnet run`) и преподаватель (проверка ООП-архитектуры на C#, классов, интерфейсов и рабочего веб-приложения).
- **Ключевой результат:** при запуске `dotnet run` (после однократной сборки фронтенда `npm run build`) C#-сервер одновременно поднимает REST API и раздаёт веб-интерфейс «ВетМед» на едином адресе, а при `npm run dev` всё работает так же, как раньше.

---

## 2. Пользовательский опыт и интерфейс

- **Визуальная неизменность:** внешний вид, палитра, типографика, боковое меню, вкладки «Рабочее место врача» и «Кабинет владельца», карточки пациентов и модальные окна **не меняются**.
- **Два равноправных сценария запуска:**
  1. **Через `cmd` и `npm run dev`:** мгновенный запуск в режиме разработки для локальной работы и демонстрации.
  2. **Через `dotnet run` или Visual Studio:** запуск решения на C# (.NET 8), где все запросы интерфейса обрабатываются ASP.NET Core контроллерами и ООП-сервисами, а статические файлы интерфейса и изображения питомцев отдаются напрямую из собранной папки фронтенда.
- **Прозрачная обработка ошибок:** C#-бэкенд возвращает те же коды ответов (`400`, `404`, `409`) и формат сообщений, что позволяет без доработок отображать в интерфейсе уведомления о занятых слотах врача или незаполненных полях.

---

## 3. Ключевые технические решения и компромиссы

- **Единый контракт API и совместимая JSON-база:**
  - *Выбранный подход:* сериализация моделей C# в формате `camelCase` и чтение/запись общего файла хранения состояния клиники с потокобезопасной блокировкой.
  - *Почему:* не нужно переписывать клиентскую часть или заводить две разные базы данных; изменения, сделанные через любой сервер, сразу видны другому.
  - *Альтернатива:* переписать API под новые маршруты и формат — отклонено, чтобы не ломать существующий фронтенд.
- **Нулевые внешние NuGet-зависимости в C#-проекте:**
  - *Выбранный подход:* использование только встроенных библиотек `.NET 8` (`Microsoft.AspNetCore`, `System.Text.Json`, `System.Linq`).
  - *Почему:* проект собирается у преподавателя максимально быстро без ошибок скачивания сторонних пакетов и конфликтов версий.
- **Явная и демонстративная ООП-модель предметной области:**
  - *Выбранный подход:* разделение на абстрактные базовые классы, доменные сущности с инкапсулированными методами изменения состояния, интерфейсы сервисов/репозитория и пользовательскую иерархию доменных исключений.
  - *Почему:* преподаватель сможет легко увидеть и оценить все базовые принципы ООП в коде.

### Соответствие интерактивных сценариев и C#-обработчиков

- **Получение и сброс состояния:** контроллер клиники загружает актуальный снимок из `IClinicRepository`, а при сбросе восстанавливает эталонный набор через `IClinicSeedProvider`.
- **Регистрация владельцев и питомцев:** создание экземпляров `Owner` и `AnimalPatient`, инкапсулированная проверка обязательных полей и обновление карточки (вес, статус, диета, аллергии, бокс).
- **Запись на приём и статусы:** `IScheduleValidator` проверяет отсутствие активной записи у врача на выбранную дату и слот, возвращая ошибку конфликта (`409`) при наложении.
- **Протокол осмотра и списание из аптеки:** фиксация `MedicalRecord` обновляет вес питомца и вызывает `IPharmacyService` для безопасного уменьшения остатков препаратов.
- **Лаборатория, стационар, вакцинация и счета:** отдельные контроллеры делегируют изменение статусов и расчёты доменным методам сущностей (`LabTest`, `InpatientTask`, `Vaccination`, `Invoice`) с централизованным перехватом доменных исключений.
- **Обслуживание сборки и Git:** настройка исключения временных артефактов сборки C# (`bin/`, `obj/`) в правилах игнорирования Git, чтобы при отправке на GitHub попадали только исходники на латинице.
